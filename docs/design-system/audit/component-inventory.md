# Shared component pattern inventory

Audit date: 2026-07-12  
Scope: tracked browser runtime under `app/`, `components/`, `features/`, and `shared/`; the DOM-based Crucible implementation is recorded separately because it is tracked but is not selected by the current router.  
Method: direct inspection of JSX/JavaScript markup, the active stylesheet import graph, CSS selectors, portals, and responsive rules. A class family such as `.studio-*` below means the named selectors and their BEM children/modifiers in the cited stylesheet, not an assumption that every selector in that namespace is visually reusable.

## Executive findings

1. **The repository has shared visual ingredients, but not a complete component API.** `shared/styles/components.css` exposes surface classes (`.cruor-ui-panel-surface`, `.cruor-ui-card-surface`, `.cruor-ui-control-surface`, `.cruor-ui-chip-surface`), `.icon-btn`, `.btn`, `.panel`, `.empty`, `.filter-combobox*`, `.context-menu`, and `.cruor-scroll-surface`. Most routes still implement their own complete controls on top of or instead of those ingredients.
2. **The shared Composer system is real current design-system work and should be retained.** `components/ui/composer-rail.jsx`, `shared/styles/composer-system.css`, and `shared/styles/composer-internals.css` are consumed by both Dark Places and Terrifying Monsters. The shared internal classes cover rails, collapsible sections, navigator filters, cards, metadata, compatibility badges, and internal scrollbars.
3. **The nominal shared `Button`, `Card`, and `CardContent` React components are not a design system.** `components/ui/button.jsx` and `components/ui/card.jsx` only pass through `className` and props. No tracked runtime module imports them. They provide no default class, variants, behavior, or accessibility contract.
4. **Several apparent canonical classes are markers without an active shared definition.** Runtime markup uses `.cruor-button`, `.cruor-button--sm`, `.cruor-button--icon`, and `.cruor-panel--modal`, but no active stylesheet defines those selectors. Their appearance comes from co-applied feature classes such as `.mvp-button`, `.map-tool-button`, or `.cruor-ui-control-surface`.
5. **Shared-looking names remain regression-sensitive.** `.panel`, `.icon-btn`, `.component-card`, `.component-navigator-modal*`, `.navigator-*`, `.meta-*`, `.room-context-menu`, `.location-map-toolbar*`, `.active`, and `.is-active` occur across multiple feature styles. They cannot be treated as safe aliases until source order and selector dependencies are migrated.

## Component Navigator: current shared work and boundary

The two current Composer navigators are separate React implementations but intentionally converge on shared semantic classes:

- Dark Places: `features/darken-location/composer/components/LocationComponentPickerModal.jsx`. Despite the filename, the current rendered surface is an inline drawer/`role="region"`, not a modal portal. It emits `.component-navigator-*`, `.cruor-composer-navigator-*`, `.cruor-composer-component-*`, `.cruor-composer-filter-chip`, `.cruor-composer-meta-*`, `.cruor-composer-compatibility-badge`, and `.cruor-scroll-surface`.
- Monster: `features/monster-composer/components/monster-composer.navigator.jsx`. The current page uses `ComponentNavigatorDrawer`; the same module also exports a body-portaled `ComponentNavigatorModal`, but the current Monster page does not instantiate that modal. It emits the same shared semantic classes plus Monster aliases.
- Shared normalization: `shared/styles/composer-internals.css` intentionally loads after each feature stylesheet and uses `.cruor-composer-shell ...` specificity to make the shared visuals authoritative.

The future canonical boundary should be a shared **visual and structural Navigator shell** (header/actions/search/filter rail/list/card/metadata/badge) with feature-provided data, compatibility decisions, card contents, and actions. Do not merge Dark Places room-constraint logic with Monster graft scoring. Do not rename the current semantic classes until both drawer implementations and the unused modal export have explicit tests.

## Raw HTML selector audit

These selectors make component extraction cascade-sensitive:

- `shared/styles/theme.css` styles `*`, `body`, `select`, `button`, `h1`, `h2`, `h3`, `p`, `input`, `textarea`, placeholders, hover/focus states, and `textarea` scrollbars globally.
- `app/home-page.css` styles `.cruor-home a`, `.cruor-home button`, headings, paragraphs, labels, inputs, and textareas by ancestry.
- `features/monster-composer/monster-composer.styles.css` has broad `.monster-shell input`, `.monster-shell select`, `.monster-shell ::-webkit-scrollbar`, and many component-descendant `button`, `strong`, `span`, and heading rules.
- Dark Places, map, Studio, and Inspirations similarly style raw buttons/inputs/headings/tables under page or component roots. Studio rule-editor on/off controls are often raw buttons inside a feature container rather than named primitives.
- `shared/styles/tooltips.css` deliberately normalizes raw content with `.cruor-tooltip :where(h1, h2, h3, p, div, span, dt, dd, dl, kbd)`.
- `shared/styles/accessibility.css` uses broad `:where(...)` and several `!important` overrides across shell, panels, cards, menus, and feature controls.

Migration must first add canonical classes without removing these rules, then narrow raw selectors only after route-by-route computed-style comparison.

## Behavior versus visual styling

Classes/data that carry behavior or state as well as appearance must remain stable until consumers are migrated:

- Generic state: `.active`, `.is-active`, `.is-open`, `.is-collapsed`, `.details-open`, `.in-build`, `.slot-full`, `.is-armed`, plus `hidden` and ARIA state.
- Composer: `.component-navigator-*`, `.navigator-*`, `.component-card`, `.meta-*`, `.location-map-toolbar*`; JavaScript uses these structures for focus, positioning, dismissal, measurements, and feature state.
- Map: `.room-context-menu`, menu/flyout selectors, `.map-viewport`, SVG overlay/handle classes, and `#cruor-map-svg` are tied to geometry, interaction, or export.
- Shell: `.site-topbar`, `.site-mega-menu`, `[data-site-mega-item]`, and accessibility datasets are tied to event delegation, focus navigation, and portal placement.
- Studio: collapse/resizer classes and rail data/state are tied to persisted widths and layout behavior.

The later design-system implementation should prefer ARIA and `data-*` behavior hooks while preserving existing classes as compatibility aliases. The complete selector dependency list is maintained in `selector-dependencies.json`.

## Confidence and gaps
